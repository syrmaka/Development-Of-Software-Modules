# Задание №1 — Разбор знакомого сервиса

**Сервис:** Wildberries

## 1. Поиск товара

**Что уходит на сервер:**
Запрос с параметрами: поисковая фраза, токен пользователя, страница выдачи.

**Что сервер проверяет:**
Валидность токена, корректность параметров, права доступа.

**Куда сохраняется:**
База данных, раздел «Недавний поиск».

**Что возвращается:**
Список товаров, количество найденных позиций.

---

## 2. Добавление товара в корзину

**Что уходит на сервер:**
POST-запрос с данными, токен пользователя.

**Что сервер проверяет:**
Наличие товара на складе и его статус, валидность ID и параметров варианта.

**Куда сохраняется:**
Запись в корзину. Если корзина привязана к сессии — может храниться в кэше до логина, после логина — в основной БД.

**Что возвращается:**
Обновлённый состав корзины, статус операции.

---

## 3. Оформление заказа

**Что уходит на сервер:**
POST-запрос с данными заказа, согласие на обработку данных.

**Что сервер проверяет:**
Актуальность остатков на момент оформления, соответствие адреса зоне доставки (его корректность).

**Куда сохраняется:**
Запись заказа в БД.

**Что возвращается:**
Номер заказа, итоговая сумма, ожидаемая дата доставки, статус оплаты.

# Задание №2 — Место для отказа (добавление в корзину)

## Пропажа сети
**Что может пойти не так:**
Запрос не дойдёт до сервера или ответ не вернётся — либо интерфейс не обновится, либо товар не добавится.

**Как ведёт себя приложение на практике:**
Показывает отсутствие связи.

## Двойной клик по кнопке
**Что может пойти не так:**
Запрос может прийти дважды (если есть защита, то всё будет нормально).

**Как ведёт себя приложение на практике:**
Защищают через блокировку кнопки после первого клика.

## Отправить пустое поле
**Что может пойти не так:**
Если фронтенд не проверяет количество, сервер получит некорректные данные. Если валидация слабая, возможны ошибки.

**Как ведёт себя приложение на практике:**
Возвращается ошибка 404 и сообщение «Товар не найден».
